Application labWhat you will learnHow to runArchitecture & workflowCode walkthrough
01

Connect the official docs server

The HTTP experiment connects to the live Claude Code documentation MCP endpoint. The agent calls its real search tool and cites a returned source. Feedback submission is excluded by the host guard.

02

Launch an external stdio process

The SDK launches the pinned official filesystem server using Node and an argument array. Only a fresh classroom folder is supplied as its allowed root. This is a separate process, unlike an in-process SDK server.

03

Load a project .mcp.json

Compare inline mcpServers with a real generated .mcp.json. The project experiment enables settingSources: ["project"] and explicitly approves the controlled project server. The application’s real .env is outside that folder.

04

Name and approve tools

Inspect actual mcp__ tool names. Compare an exact filesystem approval with an unapproved second call. The combined experiment also demonstrates a docs wildcard, limited to search by a separate host guard.

05

Distinguish permissions from availability

acceptEdits does not pre-approve these MCP calls. This app denies unresolved permission requests and records what was attempted and completed. It does not use bypassPermissions.

06

Observe actual connection state

Inspect mcp_servers at initialization and later mcpServerStatus() results. The startup experiment adds a labelled two-second server delay and an explicit wait setting. Measurements describe this run, not a universal startup time.
